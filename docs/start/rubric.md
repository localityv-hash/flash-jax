# 收录标准

这个站点的价值在于**筛选**。后训练方向每周都有几十篇新论文，真正改变做法的只有少数。这里说明我们怎么判断、怎么分级，以及页面上的数字从哪来。

::: human
我们只收“有人真的用过、实验站得住、代码能跑、同行认可”的东西。每个条目都会写明它满足哪几条，你可以自己判断信不信。
:::

## 五类证据 {#evidence}

每个条目都会标注它满足下面哪几类证据；卡片上的绿色小标签就是它们。

### 工业实践 {#industrial}

作者团队用它训练了公开发布的工业级模型或系统，或者它本身就是生产级系统。例如 DeepSeek-R1 的训练配方、Qwen3 技术报告里的蒸馏流程、verl 这样在一线团队大规模使用的训练框架。

**判断方法**：技术报告里明确写了“我们用这个方法训练了某某模型”，且该模型公开可用。

### 被工业采用 {#adopted}

至少一个**其他团队**的工业级工作明确采用或改进了它。GRPO 是典型：它来自 DeepSeekMath，之后被大量工业训练采用和修正。

**判断方法**：在别家的技术报告或代码里能找到明确引用与使用；条目的“可信度”说明里会写出是谁。

### 实验扎实 {#ablation}

有控制变量的消融、足够的规模、多基准或多种子验证，结论能直接指导实践。OpenThoughts 对 SFT 数据配方的系统消融、ScaleRL 对 RL 扩展规律的大规模实验都属于这一类。

**判断方法**：去掉某个设计后效果怎么变，文中有没有直接回答；结论是否在多个模型或数据上成立。

### 开源可验证 {#open-source}

有真实可运行的代码、数据或权重，并且能从多个信息源交叉验证内容，比如仓库、论文和第三方复现相互印证。

**判断方法**：仓库存在且在维护，关键结果有独立复现或被广泛使用。

### 社区认可 {#community}

论文引用多、在 Hugging Face Daily Papers 或 alphaXiv 上点赞多；项目 star/fork 多；博客被广泛转引、讨论，且内容经得起推敲。

**参考量级**：引用 ≥ 100（发布一年内 ≥ 30），HF 点赞 ≥ 50，star ≥ 1k。只作参考，不单独决定收录。

## 三个分级 {#tiers}

| 分级 | 规则 | 怎么用 |
|---|---|---|
| **必读** | 至少 3 类证据，且包含“工业实践”或“被工业采用”；改变了大家的做法 | 每个方向 5–8 篇，读完就能跟上主流 |
| **推荐** | 至少 2 类证据 | 做这个方向的人值得读 |
| **参考** | 1 类强证据，解决具体问题；或非常新（3 个月内）但来源可靠、值得跟踪 | 遇到对应问题时再查 |

## 不收什么 {#exclusions}

- 只刷榜、不解释为什么有效的工作；
- 没有代码、没有复现，也没有工业背书的工作；
- 结论不可执行（读完不知道该怎么改做法）；
- 营销稿，以及无法核实来源的二手转述。

## 数字从哪来 {#metrics}

卡片上的引用数、点赞数、star/fork 由持续集成在每次部署时自动抓取，每周一再刷新一次：

| 指标 | 来源 | 说明 |
|---|---|---|
| 引用 | Semantic Scholar | 按 arXiv 编号查询；新论文会偏低 |
| HF 赞 | Hugging Face Daily Papers | 只有上过 Daily Papers 的论文才有 |
| Star / Fork | GitHub | 反映关注度，不直接代表质量 |

::: pitfall 数字不是质量本身
引用和 star 有明显的“马太效应”，也偏向英文、偏向大机构，新工作天然吃亏。所以数字只是五类证据之一；一篇三个月前、有完整消融和代码的工作，可能比一篇高引用但结论过时的工作更值得读。
:::

## 发现错误怎么办 {#corrections}

发现事实错误、过时结论，或者有值得收录的工作，欢迎在 GitHub 上提 issue 或 PR。数据格式与写作规范见 [参与贡献](/contributing)。
